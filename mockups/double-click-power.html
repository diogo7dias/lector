4 · Double-click, inside a book Rows are left aligned with a fixed status column so the [X] never shifts the labels. [X] means the action cannot run right now: this page has no footnote, and paragraph numbering is off. The cursor skips those rows. Back closes. The reader page behind is never repainted.

What happens when you press

  • Power held past powerButtonDuration → sleep. Unchanged, and it always wins.
  • Power + Down → screenshot. Unchanged, and it is checked before the click logic.
  • One click, inside a book, feature on → wait 280 ms. No second click → the normal shortPwrBtn action runs, just 280 ms later.
  • Second click inside 280 ms → the bound action runs; the single-press action is dropped.
  • Outside a book → no wait at all. The power button behaves exactly as it does today.
  • Feature set to Disabled → no wait anywhere. Byte-for-byte today's behaviour.

Where the code goes

  • CrossPointSettings.h — widen LONG_PRESS_MENU_FUNCTION to 13 values, append only. Add doubleClickPowerFunction and a popupItems bitmask (one uint16).
  • SettingsList.h — one Enum row, one custom row opening the tick screen.
  • EpubReaderActivity::runBoundMenuFunction — grows from 4 cases to 12, plus the pop-up case. Each new case reuses the entry point the menu already calls.
  • New PopupItemsActivity — the tick list. Small, one file.
  • The click detector lives in EpubReaderActivity, not main.cpp, so the 280 ms wait cannot leak outside a book.

Known risks

  • Settings order is load-bearing. LP_MENU_KOSYNC == 0 and LP_MENU_DISABLED == 1 already. Any new default must be 1, never 0, or closing the menu starts a WiFi sync.
  • Grab Quote hands the picker a raw Section*. It must run last, after any live toggle that could repaginate, exactly as the Menu Hold path already does.
  • A press must act within 500 ms or die. 280 ms plus dispatch stays inside that.
