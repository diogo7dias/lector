## Fixed
- **A locked reader can leave Lector again.** Some Xteink X3 and X4 units ship with USB flashing disabled from the factory, and on those the only routes off a firmware are the SD card picker and the CrossPoint OTA Unlocker, which answers the reader's own update check with a firmware you choose. Lector refused everything that tool could offer: it installed an update only when the offered version was strictly newer, so stock, CrossPoint, CrossInk and the same version again were all turned away, and there was no override anywhere on the screen. Readers that took Lector on a locked device were stuck on it.
- **A firmware installed over Wi-Fi now stays installed.** The Wi-Fi path pointed the bootloader at the new image with rollback armed, so any firmware that does not report itself healthy on first boot, which is every firmware not built on the Arduino core, was silently undone and the device came back on Lector. The SD card path was fixed this way in 0.28.0; the Wi-Fi path now uses the same code.
- **The Wi-Fi update no longer fails for want of memory.** The download ran with no memory check and no framebuffer loan, and a TLS transfer with Wi-Fi up needs more room than the reader has late in a session. It now refuses the attempt with **Not enough memory for a secure connection** rather than retrying for a minute with nothing free, and lends the framebuffer to the transfer the way font downloads do. A firmware served over plain HTTP, which is what the OTA Unlocker does, needs neither and keeps its progress bar.
- **The recovery chord works with no SD card mounted.** Holding the chord at boot when the card was missing or unreadable ended at "SD card error", which on a locked device is the last route out gone. It now asks for a card and keeps trying, so one inserted at that point still reaches the firmware picker.

## Added
- **Settings > System > Install Other Firmware.** Installs whatever the update server offers, whatever its version and whichever firmware it is. This is the deliberate escape hatch; **Check for updates** still installs only newer stable releases of Lector. The same choice is offered on the "no update available" screen.
- **Per-device update assets.** The X4 Pro asks for `firmware-x4pro.bin` and falls back to `firmware.bin`.

## Changed
- The Wi-Fi update writes the image the same way the SD card update does: raw partition writes, then the header, chip id, segment table, checksum and SHA256 verified by reading the image back out of flash, and only then the boot record switched. The previous path leaned on `esp_ota_end`, whose image check rejects images this device runs perfectly.
- Note on trust: the update check does not verify server certificates, on any path. That is what lets the OTA Unlocker stand in for GitHub on its own network, which is the only reason a locked device can be rescued at all.
